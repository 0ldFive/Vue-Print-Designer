# AI 动作协议 · 设计

**目标**：把 AI 助手从「只会生成页面 JSON」扩展为「按动作注册表执行模板级 / 页面级 / 输出类操作」，新增行为只改注册表一处。

**方案**：建立动作注册表（id / 提示词描述 / 参数 / 是否破坏性 / 本地降级规则 / 执行函数）；提示词中的动作清单由注册表自动生成；模型在原有 JSON 里多返回一个 `action` 字段，前端统一分发执行。生成类仍走「预览 → 确认」，其余动作直接执行并写一条助手消息。

**全局约束**：

- 不引入 function calling / tools 协议，保持现有 SSE + 纯 JSON 解析链路。
- 无 `action` 字段且含 `pages` 的输出视为 `generate`，兼容旧行为。
- 本地正则只作为「未配置模型」时的降级路径，不再是主入口。
- 破坏性动作（删模板、删页）必须二次确认。
- 动作执行期间不关闭 AI 面板，保证用户能看到结果反馈。
- 文档中代码仅保留签名，实现体用一行省略注释占位。

## 现状与问题

- `useAiTemplate.send` 里只有一种输出契约：页面 JSON；因此「新建空模板」这类非页面请求只能靠 `isBlankTemplateRequest` 正则逐条拦截。
- 每加一种行为（复制、重命名、删除、切换、导出、打印）就要在 `send` 里再加一个 `if`，规则越堆越多且无法覆盖自然语言长尾。
- 提示词与实现各写一份能力说明，容易不同步。
- 新建/切换模板会触发 `designer:template-replaced`，AI 面板被关闭，用户看不到成功消息。

## 方案与取舍

- **采纳：动作注册表 + 模型返回 `action`**。语义理解交给模型，前端只负责执行；提示词清单由注册表生成，能力与实现单点维护。
- 否决 **function calling / tools**：需要重写流式客户端，且第三方兼容端点支持参差，会把可用性绑死在模型上。
- 否决 **纯本地命令解析器**：本质仍是逐条枚举正则，只是换了写法；仅保留为无模型降级。

## 动作清单

| 分组 | 动作 id | 底层能力 |
| --- | --- | --- |
| 模板 | `create_template` / `duplicate_template` / `rename_template` / `delete_template` / `switch_template` / `save_template` / `save_template_as` | `createTemplate`、`copyTemplate`、`editTemplate`、`deleteTemplate`、`loadTemplate`、`saveCurrentTemplate` |
| 页面 | `add_page` / `delete_page` / `duplicate_page` / `set_canvas_size` | `addPage`、`deletePage`、`copyPage` + `pastePage`、`setCanvasSize` |
| 输出 | `print` / `export_pdf` / `export_html` / `export_images` / `view_json` | dispatch 已有 `designer:*` 事件 |
| 导入 | `import_template` | 传入模板 JSON → 规范化 → 预览确认 |
| 生成 | `generate` | 现有 `normalize → diff → beginPreview` 链路 |

## 执行链路

```ts
// 伪代码占位：send 主体
const send = async (instruction, options) => {
  // ...（伪代码占位：省略参数与状态校验）
  if (!isAiConfigReady(store.config)) {
    const local = resolveLocalAction(prompt);
    return local ? runLocal(local) : false;
  }
  const raw = await requestAiTemplate(...);
  const output = parseModelOutput(raw); // ...（伪代码占位）
  return output.action === "generate"
    ? runGenerate(output.template)
    : executeAction(output.action, output.args, assistantId);
};
```

```ts
// 伪代码占位：注册表条目
interface AiActionDefinition {
  id: string;
  description: string; // 注入提示词
  params?: string;
  destructive?: boolean;
  localPatterns?: RegExp[];
  run(args, ctx): Promise<AiActionOutcome>;
}
```

执行结果三态：`message`（直接反馈）、`generate`（走原链路）、`preview`（导入后预览确认）。
